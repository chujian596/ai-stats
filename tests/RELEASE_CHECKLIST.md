# 发版质检清单（每版必做）

任何改动（解析规则、弹窗、样式、版本机制）在推送前必须全过，未过不许 push。

## 一、自动项（一条命令）

```bash
bash tests/release_check.sh
```

包含：
1. 语法门禁：抽出所有 `<script>` 交给 `node --check`
2. 回归：`tests/coverage_check.py` → 38 项，要求 **失败 0**
3. 线上版本核对（可选，推送后）：`APP_VER` 与 `version.txt` 一致

## 二、人工项（浏览器实测，必须逐条看结果）

启动：`cd ai-stats && (nohup python3 -m http.server 8099 >/tmp/http9.log 2>&1 &)`
页面：`http://127.0.0.1:8099/app-pro.html?nock=1&t=<随机>`
先清 `localStorage.removeItem('aiProPinVer')`

### A. 该弹窗（15 条）
特马5、平特马龙50、红波10、蓝波5、单20、双15、大15、小10、
红波单10、绿波大5、合数单10、05 17 29 10、3头10、尾3 10、16 28 49 05

判定：都弹，弹窗文案正确。

### B. 不该弹（12 条）
平特马80=80、05 10=10、连马龙兔10=10、02 15二中二10=10、
19 16 35三中三8=8、特马各5=25、特马各数5=25、特马各号5=25、
特马每个5=25、红波各5=85、红波各号5=85、狗各数5=20

判定：直接落账，金额一致。

> 注：`红波各5=85`、`红波各号5=85` 这两条 **node 测试环境算不对**（无 DOM 时波色展开路径不同），必须以浏览器实测为准，不能只看脚本结果。

### C. 多选合并
- `红波10 单20 大15` → 一个框 3 项，全选"共" = 45 元
- 整批 15 行（狗各数100 … 红波10）→ 一个框 **2 项**（平龙马、红波），选共250/共10 = **2325 元、68 项**

### D. 明细与样式
- 波色"每号X"在明细里合并成一行 `N个号 每号X = 总额`
- 选中项：浅灰底 + 黑边 + ✓；未选：白底灰字
- 确定按钮：未选完白底灰字灰边（`确定（还差N项）`），选完白底黑边黑字

### E. 其他功能
- 开奖录入、订单记录、排行榜、飞单统计、对账单、撤销开奖、功能设置弹窗能打开
- 手动录入（12 种类型）能存
- 版本入口：`?ver=v58.63` 能跳到旧版；当前版号不跳；不存在版本不跳

## 三、推送后

1. `Wait 85` 秒等 Pages 部署
2. `curl "...app-pro.html?t=$RANDOM" | grep APP_VER` 核对版本
3. 生成快照：`bash versions/snapshot.sh vXX.XX-Pro "说明"`，更新 `versions/index.html`
