### Step 2 — `order_engine/parse.py`

**不要照搬 JS 的"按金额锚点切行"。** 那套是造成"怎么改都识别不了"的根因。改用**先抽号码序列、再抽金额**的结构化扫法：

```python
import re

NUM_SEQ = re.compile(r'\d{1,2}(?:\s*[.\-/、,，\s]\s*\d{1,2})+')  # 05.17.29 / 05-17-29 / 05 17 29
UNIT     = re.compile(r'(元|块|米|钱|個|个)')
PLAY_WORD= re.compile(r'(特|平特|平|连|复式|头|尾|各)')

def extract(tokens_text):
    """一次扫出四类东西，不让它们互相抢：
       nums   号码序列（整体吃掉，绝不参与金额判定）
       zods   生肖字
       plays  玩法词
       money  剩余数字（必须是独立 token，且不在单位/号码里）
    """
```

规则要点（逐条对应踩过的坑）：

1. **号码序列整体识别**：`05.17` 是 `05` 和 `17` 两个号码，**不是小数 5.17**。
   判据：号码段由 1–2 位数字组成、且全部落在 1–49 内、且被分隔符连成串。
2. **行首"特/各/连"后面紧跟的数字是号码，不是金额**。`特05-17-29各10` 里 05、17、29 是号码，10 才是金额。
3. **金额只能来自"独立出现的数字 + 单位"或"最后一个裸数字"**。`各10米` → 10；`共70米` → 汇总行，跳过。
4. **汇总行判定**：整行含 `共/合计/总计/共计` 且不含 `各` → 直接跳过，不产生订单。
5. **玩法归一化**（顺序很重要，`平连` 必须在 `连X` 之前处理）：
   - `特号` / `特碼` / `特码` → `特`；连续多个 `特` 折叠成一个
   - 裸 `单` / `双` → `单数` / `双数`（产品表里只有这两个名字）
   - `X连YZ`（如 `马连龙兔`）→ `连肖XYZ`（否则会被解析成"马的全部号码"）
   - `平连龙虎` → 保持 `平连`，不能被拆成"平连肖"
   - 三色 + 单/双 + 大/小 任意词序 → 归一成产品表里的标准名（`绿波小单` → `绿波单小`）
6. **一注的产出**：

```python
Order = {
  "play": "特",            # 必须存在于 PRODUCTS
  "nums": [5,17,29],       # 号码注
  "zod":  [],              # 生肖注
  "xiao": [],              # 连肖用
  "money": 10,             # 每号金额
}
```

7. **金额摊法歧义 → 必须问人，不许自己猜**：

```python
# 出现以下情况返回 need_confirm
{"need_confirm": True,
 "reason": "总额摊到 N 号 还是 每号各 X",
 "options": [{"label":"总额10元摊到17号","per":0.6},
             {"label":"每号各10元","per":10}]}
```
例如 `红波10`（17 个号）、`特马兔各5`（生肖全号 vs 生肖首号）都属于这一类。

### Step 3 — `order_engine/ai.py`

AI **只兜底**，不许抢在本地前面跑。顺序固定：

```
点保存
 ① 本地 parse 全部行 → 算出订单 → 直接存（不联网）
 ② 本地有行算不出 → 才调 AI 翻译
 ③ AI 结果本地校验 play ∈ PRODUCTS
 ④ 用错词 → 带纠正提示重问一次
 ⑤ 仍不行 → 返回 need_fix，让前端弹补救窗
```

system prompt 必须包含（这段已经在 JS 版验证有效，真 API 实测 5 条全对）：

```
合法 play 词表（只能原样抄，不许自创）：
{PLAY_VOCAB}          # 从 rules.py 自动注入，不许手写

规则：
1. play 必须严格等于词表里的某一项
2. 完全相同的订单重复 N 次 → 必须返回 N 条，严禁合并
3. 只输出 JSON，不要解释
```

校验与重试：

```python
def parse_with_ai(text, retry_hint=None):
    r = call_deepseek(text, retry_hint)
    if r.get("ok"):
        bad = [d for d in r["data"] if d.get("play") and d["play"] not in PRODUCTS]
        if bad and not retry_hint:
            return parse_with_ai(text, retry_hint=bad[0]["play"])   # 只重试一次
    return r
```

**第 2 条很容易漏**：同一组号码连写三遍，AI 天然会合并成一条，等于少算 140 米。实测加这条规则后才会返回 3 条。

### Step 5 — WebView 前端改造

`assets/www/index.html` 改动很小：

1. 原来的 `doSave()` 里 JS 解析整段，替换成：

```js
async function doSave(){
  const text = document.getElementById('input').value;
  const r = await fetch('/api/order/parse', {method:'POST',
        headers:{'Content-Type':'application/json'},
        body: JSON.stringify({text})}).then(x=>x.json());

  if(!r.ok) return showFixDialog(r);

  if(r.need_confirm.length){          // 金额摊法歧义
    const picked = await askUser(r.need_confirm[0]);
    if(!picked) return;
    r.orders.push(...picked);
  }
  if(r.need_fix.length){              // 认不出的行
    const fixed = await showFixDialog(r.need_fix[0]);
    if(!fixed) return;
    return doSaveWith(fixed.text);
  }
  await fetch('/api/order/save',{method:'POST',
        headers:{'Content-Type':'application/json'},
        body: JSON.stringify({orders:r.orders})});
  renderAll();
}
```

2. **AI 成功后绝对不许把结果写回输入框**。输入框里永远是客户原话。

3. 保留现有三样：号码按波色着色、右上角版本号、保存/清空两个按钮。

## 4. 验收标准（硬指标，不达标不算完）

```bash
python3 -m pytest tests/    # 38 条必须 0 失败
```

| 用例 | 期望 |
|---|---|
| `澳特：/05-17-29-09-21-33-45各数10米/共70米` | 1 单 · 70 米 · 7 号 |
| 上面那组连写三遍 | 1 单 · **210 米 · 21 号**（不许合并成 70） |
| `特5.17.29.9.21.33.45各10` | 1 单 · 70 米 · 7 号 |
| `05 17 29各10` | 1 单 · 30 米 · 3 号 |
| `马连龙兔10块` | 抽到 3 个肖，不是"马的全部号码" |
| `绿波小单20块` | play = `绿波单小`（归一成功） |
| `红波10` | 必须返回 need_confirm（摊法歧义） |

- **断网可解析**：关掉网络，上面号码类用例照样出单（AI 只是兜底）
- **不堵死**：任何一种写法，最坏结果是弹补救窗，不允许出现"无法识别…"然后什么都不发生
- **不污染输入**：AI 参与解析后，输入框里仍是客户原文

## 5. 红线（这 6 条不许动）

1. **客户版不许带 AI、不许带任何 key**（客户版 `app.html` 是纯本地）
2. **号码必须按波色着色**：红 `#c0392b` / 蓝 `#2471a3` / 绿 `#1e8449`；特号**不画圈**
3. **一次保存 = 一个单**，所有行合并成一单
4. `共XX米` 是汇总行，**不许重复计钱**
5. **完全相同订单重复 N 次 → 计 N 次**
6. **金额摊法有歧义必须问人**，不许替客户决定

## 6. 已经踩过的 4 个坑（照抄别再踩）

| 坑 | 现象 | 根因 |
|---|---|---|
| 点分隔号码被当金额 | `05.17` → 拆成两行，报"无法识别：特" | 拿 `parseFloat("05.17")=5.17` 当金额，且前一字符是"特" |
| 行首"特"紧贴号码 | `特05 17 29各10` 同样切坏 | "特"被当金额锚点 |
| AI 抢在最前 | 点保存先调 AI，AI 不通就直接报错，本地没机会 | 顺序反了 |
| AI 改写输入框 | 客户原文被 AI 结果覆盖 | 把 AI 结果写回 `input.value` |

**这四条的共同教训：解析器的失败必须是"可恢复"的，不能是"终止"。**
