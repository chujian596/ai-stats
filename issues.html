一、录单系统 · 金额口径（v58.135 → v58.156）
#01 · v58.135
凑整多飞的钱没人记账已修
现象
按 5 元档凑整飞出去，实际付给上家的钱比「应飞原额」多/少，自留现金和净盈亏全对不上。
根因
当时只记了「该飞多少」（flownPerPos），没记「实际付了多少」。
修法
新增 flownReal 记实际实付，配 flownRealOf(k) / realFlyAmount(k,bet) 统一出口。
怎么查
任取一个号，比对「原额飞」与「凑整后飞」两个数，再看自留现金是否按后者扣。
#02 · v58.149
确认一次，已飞记录加两倍已修
现象
下 3 飞 5、下 5 飞 5 这种小额单，界面显示「已飞累计 860」，实际只该 430。用户直接指出「860 不可能这么多」。
根因
confirmThisRoundFly() 里同一行 flownReal[key] = ... + flyShowAmt(l.amt) 写了两遍，确认一次加两倍；另有一个分组确认函数该写没写。
修法
删净重复，补齐分组确认；加载时加自愈：若 r ≈ 2p 按原额纠正。
怎么查
确认一次后立刻读 localStorage 的 flownReal，和 flownPerPos 比，比值 ≈2 就是翻倍。
#03 · v58.150
自愈把凑整反过来抹平已修
现象
明细显示「已飞累计 404」「凑整差额 0」，但用户实飞 430（21/33 各 105、06 90…），差 26 凭空消失。
根因
上一条的自愈把翻倍值改回「原额」，把凑整一起抹掉了。
修法
自愈改成按号重算 flownReal[k] = flyShowAmt(p)；再加第二类自愈：r === p 但 flyShowAmt(p) !== p 时判为「凑整被抹平」。
教训
写自愈要「按正确公式重算」，不要「往回调一个值」——回调会丢信息。
#04 · v58.151
三个地方各算各的，差 26已修
现象
结算弹窗、飞单明细、顶部汇总三处净值不一致。
根因
顶部 renderSplit 还在用 partner（阈值原额、不含凑整、不含早前已飞）。
修法
三处统一走 realFlyAmount；开奖后自留额从 min(下注,阈值) 改成「下注 − 实际飞出」；反水按实际飞出去算。
怎么查
固定同一盘数据，在「全部已飞 / 一笔没飞 / 只飞一半」三种场景下比三处净值，必须完全相等。
#05 · v58.152
关闭凑整时文案说谎已修
现象
不勾「金额凑整」时，明细还写「凑整差额 0（飞额已是 5 的倍数）」，其实根本没凑。
修法
关闭时改「未凑整，按原额飞」；若历史确实按凑整多付过，补一句「历史确认时按凑整多付了 X」。已付的钱不倒回。
怎么查
四组：凑整开已确认 / 关闭沿用历史 / 关闭重置后重确认 / 关闭一笔没飞。
#06 · v58.153
已飞比该飞还多，三行数互相打架已修
现象
总单 630、阈值 21 该飞 162，却显示「已飞累计 430」「本轮该飞 1159」「已飞比分账多 433」「自留现金 35」。
根因
「飞出去合计」用原额、「本轮该飞」扣了已飞、「分账多」拿两个不同基准相减。
修法
统一基准 _fr.totalFly − _alreadyReal；已飞超该飞 20 元以上直接红字提示「跟当前单/阈值对不上」；自留现金拆成「现在手上 / 飞完后」两行。
#07 · v58.154
清掉旧单，旧飞单记录还赖着已修
现象
旧单已清、只录今天 630 的新单，界面仍显示「已飞 430」「自留现金 35」。
根因
clearOrders() 和日结滚存只清 orders，没清 flownPerPos / flownReal；飞单记录是按号码存的，旧号今天没下注也照样算。
修法
三处同时清并回写 localStorage；realFlyAmount 遇「今天没这号」返回 0、遇「已飞超过该飞」只按当前阈值计；已飞累计只统计今天单里还有的号。
怎么查
清单一组、日结一组，各看一遍已飞是否归零。
#08 · v58.155
已飞 113，三中三只有 110已修
现象
三中三合计 110，顶部「已飞(实际)」显示 113。
根因
getThisRoundFly().already 直接累加所有 flownPerPos，没做「已飞是否超过该飞」判断，旧记录残留 3 元。
修法
特号、平特、二中二三中三三处统一过滤：已飞 > 该飞 → 视为旧记录不计。
#09 · v58.156
点了重置，数字还挂着已修
现象
取消「即飞产品自动复制」+ 点「重置已飞」，侧栏显示已飞 0，顶部仍显示 113。
根因
resetFlown 只重绘了侧栏两个节点，没触发整页重绘；顶部三个数在 renderRisk 里生成，函数没被再调用。
修法
重置后调 renderAll() 并显式补 renderRisk()。
教训
改完数据一定要确认「所有显示这个数的位置都重绘了」——同一数据往往有 2~3 处 UI。
#10 · v58.139 / 140 / 147
削峰面板看不懂、点了没反应已修
现象
自造术语（亏损线、基准中位数、买 5.2）；模式按钮副标题写死反了；点「按削峰档 47」没变化。
根因
术语脱离业务；副标题硬编码「赚多·亏多 / 稳·亏少」；两个模式数值相同时按钮只有边框色差，看不出谁在跑。
修法
全部改白话（现在每号能留 X / 安全线 35 元/号 / 多飞 1 元换 5.2 元安全）+ _lvTag(n) 动态副标题 + 生效按钮实心高亮「✓ 正在用」+ 下一行大字说明当前按哪个档算 + 数值相同提示「点哪个都不变」。
#13 · v58.157
勾上即飞，已飞金额不出现已修
现象
重置归零后勾选「即飞产品自动复制」，侧栏已飞显示 110，顶部三数仍显示已飞 0。
根因
开关的 onchange 只刷新侧栏摘要，没重绘整页；顶部三数在 renderRisk 里生成。
修法
三个开关（即飞产品 / 金额凑整 / 香港单自动飞）统一走 afterFlyFlagChange()，一起刷摘要+整页+风险面板。
怎么查
点任一开关后，对比侧栏「已飞」和顶部「已飞(实际)」，必须同值；不同就是没重绘。
二、资料系统 · 更新与期号
#11 · v58.33
抓了数据但页面永远停在 319 期已修
现象
今天 20:05 已抓取（2350 栏），页面仍显示「上次更新 2026/11/15」、319 期。
根因
stats.html 把期号写死成 319：data/forum-319.json、consensus-319.json、cross-319.json… 全部固定路径，新数据生成了也读不到。
修法
新增 data/latest-period.json（归档时写入当期）；页面先读它再拼路径（fetchLatestPeriod → LATEST_PER）。
怎么查
看线上 /data/latest-period.json 是否 200；再确认 data/forum-{期}.json 存在；页面顶部期号是否跟着变。

三、上线前必过自检
录单系统（每次改 app-pro.html 都跑）
  • 语法：抽 <script> 拼 /tmp/_chk_app-pro.js，node --check
  • 订单矩阵 54 项：失败必须 0（「需确认」是正常弹窗流程，不算错）
  • 发版硬校验 38 项：版本三处一致（APP_VER / version.txt / app-pro-backup.html）
  • 金额断言 43 条：出现 ❌ 即停，不准推
  • 凑整 5 档全表 + realFlyAmount 5 组 + 自愈 6 组 + 三处一致性 3 组
  • 四段一把跑：bash tests/release_check.sh
  • 改完页面先 cp app-pro.html app-pro-backup.html 再校验（漏了必挂「备份同构」）
金额类问题排查顺序（按这个走，不猜）
  • 先问：这个数是「原额」还是「实际实付」？基准不同先分清
  • 再查三处是否同源：结算弹窗 / 飞单明细 / 顶部汇总
  • 再查是否扣了「还没飞出去」的钱（待飞不该进自留现金）
  • 再查已飞是否超该飞（超了就是旧记录，不是真飞了那么多）
  • 最后才怀疑凑整本身
资料系统（每期更新后看）
  • 网络：/data/latest-period.json 200，期号 = 本期
  • 文件齐：forum / ratio / three / pingte / tpl 五个 JSON 都在
  • 数量对：帖子数、推票、杀票不为 0，且与前一期量级接近
  • 页面：顶部期号、上次更新时间都变了
  • 图库 30 栏识图是另一条流程（要逐张看图），缺了只影响「本期数据」标签
四、几条硬规矩（踩出来的）
  • 数据要真实，不倒回：已付的钱不能因为关个开关就变少
  • 一处改，处处对：同一个数有多处 UI，改完必须全量重绘并逐处比对
  • 自愈按公式重算，不要往回调值
  • 写入只写一次：确认类函数写完立刻读 localStorage 复核，防重复累加
  • 清数据要清干净：订单、飞单记录、缓存三样一起清
  • 期号不写死：所有按期的路径都从 latest-period 拼
  • 改完必跑四段校验，通过才推，推完核验线上版本号与特征串
